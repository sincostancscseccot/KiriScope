# 内容过滤器插件模板

此模板用于开发确定性的 `IContentFilter` 实现。过滤器只接收已解压的条目缓冲区及其逻辑偏移，原地变换该缓冲区；它不读取游戏目录、不联网、不启动进程，也不采集运行时数据。

## 当前接入边界

阶段 6 提供模板、清单格式和方案元数据，但**不会自动发现或加载外部 DLL**。插件 DLL 等同受信任的本机代码：使用前应审计来源、许可证、清单和 SHA-256，并由后续显式注册机制接入。请不要把未审计 DLL 放入共享知识库，更不要将游戏密钥、商业资源或未验证参数提交到该目录。

`manifest.json` 描述建议的外部发布身份；它不是自动加载开关。`factoryType` 是为未来、显式的参数化注册预留的名称，当前主程序不会反射或实例化它。

## 开发约束

- 只引用 `KiriScope.Plugins.Abstractions`；算法实现不得依赖 GUI、CLI、运行时 worker 或网络库。
- 对相同 `ContentFilterContext` 与输入字节必须产生相同输出；`LogicalOffset` 是解压后条目内的连续偏移。
- 无效配置应明确拒绝，预期转换失败使用 `ContentFilterException`；始终响应取消令牌。
- 参数、适用样本版本、样本 SHA-256、复现命令和完整格式验证结果应写入版本化知识库条目，而不是通过文件名猜测。
- 测试必须覆盖：描述符/清单一致、有效和无效配置、确定性、整块与分段等价、取消、候选管线只在 `FormatValidated` 后接受，以及源文件不被修改。

## 目录

- `src/`：最小、无操作的确定性参考实现和为将来注册准备的工厂示意。
- `schemes/`：合成参数的方案形状示例，不能由当前内置加载器直接执行。
- `tests/`：应复制到正式测试项目的测试骨架。
- `samples/`：仅放合成或可公开再分发的最小样本。

替换 `example.*` 身份、许可证和来源字段后，再把插件代码放到受审计的仓库位置。任何“已支持某作品”的声明都必须绑定具体版本、样本哈希、复现命令与 `FormatValidated` 或 `ContentUsable` 证据。
