# 静态分析与候选报告

阶段 4 的静态分析器只读取输入字节，不加载、执行、注入或修改目标文件。它为 PE/插件目录生成可机读 JSON，以便把观察结果与后续研究结论分开保存。

## 命令

```powershell
kiriscope analyze pe <binary>
kiriscope analyze directory <game-directory>
kiriscope analyze archive <binary> <new-report.json>
```

`analyze pe` 输出输入文件的绝对路径、SHA-256、大小、PE 头、节、直接导入、受限字符串扫描和常量观察。`analyze directory` 递归清点 `.exe`、`.dll` 和 `.tpm`，再将已解析导入名称与同目录文件名建立候选关系。目录遍历有文件数量上限，并跳过不可访问路径。

`analyze archive` 以新文件方式写入研究归档：目标路径已存在时失败，绝不会覆盖旧结论。归档记录输入身份、完整静态报告、生成时间和等价复现命令，但不嵌入原始二进制内容。

## 证据等级

报告中的 `Findings` 有两个明确等级：

- `ObservedFact`：解析器直接从输入字节得到的事实，例如有效 PE 头、导入模块、可打印字符串或某个常量的实际偏移。
- `HeuristicCandidate`：由多个事实聚合出的研究线索，例如 CxEncryption 相关文字和常量的组合。它不证明算法、兼容性、密钥、参数或可用明文。

因此，单个字符串、常量或导入项都不能作为“支持某游戏”或“解密成功”的声明。尤其是工具自身也可能包含检测规则的文字或数值，产生的结果仍只是一项启发式候选。

## 边界与安全性

- 单文件默认最多读取 256 MiB；超限时只返回带哈希的警告报告。
- PE 解析会验证 DOS/PE 头、节范围、RVA 映射和导入表边界，并在异常输入上报告诊断而非猜测结构。
- 字符串与常量的发现数量受限；节熵仅针对已验证的原始节范围计算。
- 输入以共享只读方式打开；所有输出均需显式指定到输入树外的路径。

针对具体作品的方案，仍须以合法样本、版本身份、参数来源、完整资源格式验证和可复现研究记录为依据。
