# 一键式 KiriKiri 解包器：产品契约

> 本文件定义 KiriScope 的**最终用户体验和验收标准**。它优先于早期“研究工作台”措辞；底层的分析、过滤器、知识库和运行时能力都是实现这一体验的手段，而不是普通用户必须操作的界面。

## 目标体验

普通用户只需完成三项输入：

1. 选择一个游戏目录或一个 XP3 归档；
2. 选择要导出的资源类型（全部、图片、音频、脚本或其他可识别类别）；
3. 选择一个尚不存在、且不在游戏目录内的导出位置。

点击“开始解包”后，KiriScope 应自动完成发现、识别、方案匹配、提取、可用性验证和结果汇总。普通流程不得要求用户理解或手动选择 scheme JSON、算法名称、密钥、Adler-32、进程 PID 或外部分析工具。

```text
游戏目录 / XP3 ──> 自动发现归档 ──> 自动识别与方案匹配 ──> 按资源类型提取
                                                        │
导出目录 <───────────────── 验证、命名、去冲突、进度和汇总 <┘
```

## 用户可见的主界面

主界面应是一个任务向导，而不是研究工具集合：

| 区域 | 用户操作 | 程序负责的工作 |
|---|---|---|
| 输入 | 选择游戏目录或 XP3 | 递归发现 XP3，识别可执行文件/插件，按风险和相关性排序。 |
| 导出内容 | 选择“全部 / 图片 / 音频 / 脚本 / 其他” | 将文件扩展名、内容签名和解析结果映射为可解释的资源类别。 |
| 导出位置 | 选择新目录 | 防止覆盖、路径逃逸、写回游戏目录和无效文件名。 |
| 开始解包 | 点击一次 | 生成任务计划，自动选择已验证的兼容配置，显示实时进度、跳过原因和结果统计。 |
| 结果 | 打开导出目录或查看报告 | 区分已导出、已验证、已转换、跳过、失败和需要研究的条目。 |

“高级 / 研究”区域可以显示方案 JSON、指纹、静态分析和运行时证据，但它不得阻塞标准用户的正常解包流程。

## 自动化规则

### 标准或未加密 XP3

程序读取索引、提取与资源类型筛选匹配的条目，并在适用时验证或转换资源。用户不需要额外配置。

### 已知加密或定制变体

程序依据归档、可执行文件、插件及版本的**内容指纹**自动匹配经过验证的兼容配置。scheme JSON 是内部数据格式：它可被知识库和开发者使用，但普通用户不应被要求选择它。

自动匹配必须记录命中的配置 ID、版本、样本/证据范围和验证结果；不得仅根据游戏目录名或文件名套用配置。

### 未知或未验证的保护

程序仍应导出可以安全导出的未保护资源，并清楚汇总不能处理的条目及原因。它不得伪称已解密、不得把原始密文伪装成资源，也不得要求用户盲猜密钥。

未知样本可在用户明确选择后交给“高级 / 研究”流程收集静态或受控运行时证据，用于开发新的兼容配置；这与普通解包任务分离。

## 最终验收场景

| 场景 | 用户输入 | 成功标准 |
|---|---|---|
| 标准 XP3 | 游戏目录、图片、全新导出目录 | 自动找到归档，仅导出图片类资源；报告显示归档、条目数、导出数和跳过原因。 |
| 多归档游戏 | 游戏目录、全部、全新导出目录 | 自动处理相关归档，稳定解决同名冲突，按来源归档保留目录结构。 |
| 已知加密游戏 | 游戏目录、资源类型、全新导出目录 | 不要求用户选择 JSON；自动选用与指纹匹配且已验证的配置，并记录配置版本。 |
| 仅导出音频或脚本 | XP3、音频或脚本、全新导出目录 | 不扫描/写出不匹配的资源；结果按类别统计。 |
| 未知加密游戏 | 游戏目录、全部、全新导出目录 | 可导出的内容正常导出；其余明确标为“需要兼容配置”，并提供可选研究入口。 |
| 错误输入 | 非 KiriKiri 目录、损坏归档或已有输出目录 | 不修改游戏文件，不覆盖已有输出，给出可操作的错误信息。 |

## 诚实边界

KiriKiri 允许每部作品在自己的程序中实现任意解密代码和密钥。因此，固定版本的软件无法诚实地承诺自动解开所有未知作品。KiriScope 的承诺是：

- 对标准格式和已纳入兼容库的作品提供一键式解包；
- 对未知变体自动识别失败位置，避免产生误导性“成功”；
- 通过可审计的静态与受控动态研究不断把新作品沉淀为下一次无需手动配置的一键兼容项。

所有操作仅应针对用户拥有或已获授权的游戏副本。导出永远写入新目录，不修改游戏目录、现有归档或可执行文件。
