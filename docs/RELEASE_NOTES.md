# 发布说明

## 使用与安全声明

KiriScope 仅供学习、研究、格式兼容性分析，以及处理你拥有或已取得明确授权的副本。请遵守所在地法律、软件许可协议、著作权和数字内容保护规则；不得将本项目用于未经授权的解密、提取、复制、传播、规避技术保护措施或其他违法用途。

## 0.1.0-preview.27

- 修复 `preview.26` 在部分使用自定义 KiriKiri 存储层的受保护输入上将 XP3 原始密文字节错误报告为“运行时已验证资源”的问题。运行时辅助 DLL 现在只通过游戏已注册的存储 API（包括自定义 `archive://` 存储层）获取有效资源流，不再回退为直接读取归档记录。
- 索引 Adler-32 一致的流以校验确认导出；不一致的流只会在可识别资源格式或 KiriKiri 脚本结构成立时导出，并以 `RUNTIME_CAPTURE_STRUCTURE_VERIFIED` 明确标注。无法证实的字节不会计入成功。
- 新增 MPEG Program Stream 和 OpenType 字体签名识别，避免这些已解码资源因扩展名或索引记录异常而丢失。

### 已验证

- 对获授权的受保护 KiriKiri 样本执行全量运行时回归：所有导出项都经索引校验或内容结构确认；抽样核验的 PNG、OGG、TJS、MPEG 与字体均为有效格式，非资源提示会明确跳过。
- `preview.26` 的“7,536 条全部已验证”结论已撤回：当时输出内容包含未解码字节，不能作为成功证据。

## 0.1.0-preview.26

- 修复受保护 XP3 的运行时索引使用哈希名时，会把每包附带的“受保护归档”版权提示文本当作待导出资源的问题。现在 GUI 利用 XP3 v3 `hnfn` 映射识别该哈希别名，和静态路径一样将其作为非资源提示项明确跳过。
- `RUNTIME_CAPTURE_MISSING_RESOURCES` 对真实资源仍保持严格：辅助 DLL 仍写入失败状态且实际落盘检查仍是成功前提；本次修复只移除已由归档映射证明的提示记录，不掩盖写入故障。

### 已验证

- 该版的运行时全量回归确认了捕获文件存在与非资源提示跳过逻辑；其“所有条目已验证”的历史结论已由 `preview.27` 的内容验证更正，不能作为已解码资源的成功证据。
- 自动化测试 129/129 通过，包括受保护归档提示不会计入一键导出条目的回归测试。

## 0.1.0-preview.25

- 修复运行时捕获辅助 DLL 的清单白名单遗漏：它此前会生成“已写入、索引校验未确认”(`V`) 状态，却在写入清单时把该状态静默丢弃。因此某些作品会出现“全部捕获文件已经存在、但仅一条被确认”的假性 `RUNTIME_CAPTURE_MISSING_RESOURCES`。现在 `V` 状态会保留并由 GUI 与实际落盘文件逐项核对。
- 当完整运行时流的索引 `FileHash` 不等于标准 Adler-32 时，辅助 DLL 不再将同一流重读、重写三次；它会保留单次完整写入并立即报告校验未确认。这避免在游戏的启动线程重复处理大容量语音或视频资源。
- 成功结果新增“索引校验确认/未确认”汇总诊断，便于复核实际捕获状态。

## 0.1.0-preview.24

- 修复运行时捕获代理会对 `OriginalCreateStreamByIndex` 已返回的解码流再次调用作品提取过滤器的问题。该重复过滤会把受 Cx 保护的资源重新加密：文件虽已写入，却以错误的 Adler-32 被标记失败。
- 移除代理的后台延迟枚举线程。它过去会从非 KiriKiri 引擎线程调用存储 API，可能在受保护启动器进入标题界面后造成闪退；捕获现改由引擎线程首次成功打开真实资源时启动一次，因此不依赖某些 Cx 变体从不调用的提取过滤器回调。
- 对引擎已完整写入、但 XP3 `FileHash` 不等于标准 Adler-32 的流，记录新的“索引校验未确认”状态，而非伪报写入失败。KiriScope 仅在实际文件存在后继续进行内容识别、结构验证和导出。
- `RUNTIME_CAPTURE_INCOMPLETE` 与 `RUNTIME_CAPTURE_MISSING_RESOURCES` 现在携带实际使用的内嵌 x86 辅助 DLL SHA-256，便于确认测试没有复用旧缓存。

## 0.1.0-preview.21

- 修正 preview.20 对运行时启动目标的误判：恢复可启动启动器优先级，`VERSION.dll` 导入和保护段特征仅作为诊断信息，不再覆盖汉化或受保护启动器的实际兼容性。
- 运行时等待逻辑会在启动器退出后继续观察其子进程，直到捕获完成或整条启动链结束。成功和失败诊断会记录观察到的进程链。
- 继续报告枚举请求、代理声明捕获和实际落盘数，以区分启动链未完成、代理未捕获和文件写入失败。

## 0.1.0-preview.20

- 运行时回退不再按 EXE 体积选择启动目标。它会只读探测 x86 PE 的导入目录，优先启动直接导入 `VERSION.dll` 的 KiriKiri 引擎，并降低带 `.enigma*`、`.vmp*` 或 UPX 段特征的保护启动器优先级。
- `RUNTIME_CAPTURE_MISSING_RESOURCES` 现在会报告所选 EXE、枚举请求数、代理声明的捕获数和实际落盘数；成功结果也会记录运行时启动目标，便于复核兼容性。
- 新增 PE 启动目标探测回归测试；完整自动化测试通过 128/128。

## 0.1.0-preview.19

- 修复 XP3 v3 的 `hnfn` 文件名映射：优先用归档内完整 MD5 别名恢复真实路径，而不是以可能冲突的 Adler-32 作为主键。现在可恢复 `bgimage/bg001a.png`、`gt/gt0001.ogg` 等原始路径。
- 同一归档内的同名变体不再覆盖或失败；首项保留原始文件名，随后条目以 `__duplicate-002`、`__duplicate-003` 等稳定后缀导出。
- 无路径映射时，已识别的内容会补充安全的类型扩展名；受保护归档中的版权声明记录不会被当作游戏资源导出。

### 已验证

- 在获授权的受保护 KiriKiri 样本上完成全量验证：多份 XP3 索引均已解析，输出路径保持唯一且不使用 32 位哈希名；空数据或校验无效的占位索引会被安全跳过。

## 0.1.0-preview.17

- 一键解包新增“静态方案 + 当前输入 Adler-32 证明”路径。内置配置不会按游戏名称直接启用；只有在当前所选 XP3 中至少两条标记加密条目经解密后匹配索引 Adler-32，才会自动选中。
- 新增受 SHA-256 绑定的静态方案清单与 Cx 参数文件；Cx 控制块支持 `base64le:` 小端编码，便于分发完整的 1024 项参数表。
- 对“被标记加密、实际为明文”的启动/引导条目，只有过滤后校验失败且原始字节重新匹配索引 Adler-32 时才接受明文；任何其他失败仍保留为跳过，不会伪报解密成功。
- 不再将扩展名缺失的哈希路径误报为“路径类别与内容不一致”。真实样本中仍保留的六个跳过项均为索引自相矛盾或空的占位记录，不是可导出的资源。

### 已验证

- 在获授权的受保护 KiriKiri 样本上完成全量验证：多份 XP3 索引均已解析；重复、截断、空数据或校验异常的索引会被安全跳过，不会被报告为可用资源。

## 0.1.0-preview.16

- 一键解包的 KiriKiri 运行时回退现在会恢复受保护 XP3（包括 `cbg:` 文件名表）中的原始资源路径，再按真实路径请求游戏运行时流；不会再将不透明索引名对应的原始字节伪报为已解密资源。
- 对多层游戏目录和游戏自带 `version.dll` 增加隔离兼容处理：原目录不写入，暂存目录保留原代理并仅在副本中使用 KiriScope 运行时捕获代理。
- 运行时导出会验证每个请求流是否实际写出；版权提示条目会明确作为非资源跳过，同一原始路径的重复 XP3 索引项会去重并报告，避免重复读取和虚高计数。
- 已在另一组获授权的 KiriKiri 输入上完成全量运行时读取验证；抽检 PNG、OGG 和 PSB 均具有正确内容签名。

## 0.1.0-preview.11

- 默认“一键解包”流程现在会在导出后对受支持的资源签名执行有上限的结构验证；结果分别统计已识别、通过结构验证、未验证，以及路径类别与实际内容签名不一致的条目。
- 验证直接使用输出文件流，不会为了评分把整个大文件再读入内存；超过 64 MiB 的资源明确记录为未验证，且原始导出保留不变。

- 研究包继续移除静态分析中发现的原始二进制字符串，只保存结构化静态结论、哈希、XP3 摘要、知识扫描和外部报告的哈希引用。
- 发布包不再携带插件模板的 `bin/obj` 构建缓存；发布脚本会在生成 ZIP 后验证 GUI、CLI、双架构 worker、知识库和模板缓存排除规则。

### 已验证

- Release 构建通过，完整自动化测试 114/114 通过。
- 新增端到端回归：一键解包报告的资源验证序列化、PNG 结构验证、类别不一致诊断、未支持脚本验证跳过，以及高级研究包的输出安全与脱敏边界。

### 已知边界

- 固定版本不能诚实地自动处理任意未知的 KiriKiri 加密变体；只有受信任知识库中已验证、精确 SHA-256 且唯一命中的配置才会自动应用。
- 未提供 Authenticode 证书时，发布包仍会生成 SHA-256 清单，但可执行文件保持未签名状态。
