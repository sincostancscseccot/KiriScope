# 架构文档

KiriScope 当前实现遵循“核心模型在内、格式与研究能力在中、用户入口在外”的依赖方向。面向用户的功能范围请看[当前可用能力](../user-guide/CAPABILITIES.md)。

| 层次 | 组件 | 责任 |
|---|---|---|
| 核心 | `Core`、`IO`、`Plugins.Abstractions` | 证据等级、诊断、哈希、安全输出路径和稳定过滤器契约。 |
| 格式与资源 | `Xp3`、`Resources`、`Filters.BuiltIn` | 不依赖 GUI 的 XP3、资源格式与内容过滤实现。 |
| 研究与知识 | `Analysis`、`Integrations`、`Knowledge` | 静态观察、外部工具适配、证据归档、知识库匹配与差异比较。 |
| 运行时 | `Runtime`、`Worker.Protocol`、`Worker.X86/X64` | 默认关闭的、协议化的只读进程与模块证据采集。 |
| 用户入口 | `Cli`、`Gui` | 参数校验、授权确认、呈现结果与生成可复现命令。 |

## 关键边界

- 内容过滤器处理已经解压的 XP3 条目缓冲区；它们不负责索引解析，也不根据游戏名自动选择方案。
- `Runtime` 通过受控 x86/x64 worker 与目标进程隔离。采集范围仅为显式授权的进程/模块元数据或用户导入的 ProcMon CSV，不包含注入、内存读取或驱动控制。
- `Integrations` 只在用户显式提供外部工具路径时调用 Ghidra 或 FreeMote；工具输出会被记录和验证，缺失工具不会破坏内置分析。
- 所有会创建产物的路径均使用无覆盖写入规则；运行时、静态和知识库报告携带输入哈希、时点与复现命令。
